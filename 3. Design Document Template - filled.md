**3. Design**

**Overview:**
- **Purpose:**: Provide a design summary for the Video Lecture Q&A platform that ingests lecture videos, transcribes them, builds vector embeddings, and serves a retrieval-augmented QA (RAG) experience via a web frontend.
- **Scope:**: Backend API (FastAPI), RAG service (vector ingestion + query), Frontend (Vite + React + TypeScript), data stores (PostgreSQL for relational data, Chroma/SQLite for vector chunks), and deployment (local scripts, Docker).

**High-level Architecture:**
- **Frontend:**: [frontend](frontend) — Vite + React + TypeScript app exposing UI pages (login, dashboards, library, player, admin). Communicates with Backend API (port 8000) and RAG service (port 8100) as needed.
- **Backend API:**: [backend/app](backend/app) — FastAPI application that provides user management, video metadata, ingestion control, and integrations with the RAG service. Runs on port 8000 during development.
- **RAG Service:**: [rag](rag) — Separate FastAPI service that handles transcription, chunking, embeddings, Chroma/SQLite vector store, ingestion CLI, and query endpoints. Runs on port 8100.
- **Databases & Storage:**: PostgreSQL (primary relational DB, database name: `video_lecture_transcript`), local Chroma/SQLite for vector store at `rag/chroma_db/chroma.sqlite3`, media files under `media/`.
- **Third-party / Integrations:**: Supabase migrations present in `frontend/supabase/migrations/`. External embedding/LLM providers configured via environment variables (GROQ_API_KEY, etc.).

**Component Details:**
- **Frontend (UI):**: Sources in `frontend/src`. Key pages under `frontend/src/pages` (Admin*, User*). Authentication context in `frontend/src/lib/auth-context.tsx` and API client in `frontend/src/lib/api.ts`.
- **Backend (API):**: FastAPI routers in `backend/app/routers` (alerts, analytics, auth, chats, complaints, users, videos). Security helpers in `backend/app/security.py`. Database bootstrap and seeding utilities in `backend/seed.py` and `backend/create_db.py`.
- **RAG pipeline:**: Chunking, embeddings, and ingestion are implemented under `rag/pipeline` (chunking.py, embeddings.py, ingestion.py, vectorstore.py). Transcription and Whisper integration referenced in `rag/pipeline/transcription.py`; ffmpeg is required for audio processing.
- **Vector DB & Viewer:**: Chroma DB files are under `rag/chroma_db/`. RAG service exposes a local viewer at `/viewer` (see RUN_COMMANDS.txt instructions).

**Data Flow:**
1. Video Ingestion: Operator triggers ingestion via CLI or backend endpoint. Video stored in `media/`.
2. Transcription: RAG service runs Whisper (ffmpeg required) to produce a transcript.
3. Chunking & Embedding: Transcript is split into chunks (`rag/pipeline/chunking.py`) and embeddings are produced (`rag/pipeline/embeddings.py`).
4. Vector Storage: Embeddings saved to Chroma/SQLite (`rag/chroma_db`).
5. Querying: Frontend/backend sends user query → RAG service performs semantic search + RAG chain to produce answer, optionally calling external LLMs via configured provider keys.

**APIs & Endpoints:**
- **Frontend:**: `http://localhost:5173` (dev UI).
- **Backend (FastAPI):**: `http://localhost:8000/docs` for interactive API docs during dev.
- **RAG Service:**: `http://localhost:8100/docs` and Chroma viewer at `http://localhost:8100/viewer`.

**Security & Configuration:**
- **Environment:**: Each service uses an `.env` (or `.env.docker`) file. Secrets include DB passwords and API keys (GROQ_API_KEY). Do not commit secrets.
- **Auth:**: Backend includes `auth` router and security utilities. Frontend stores session state in `auth-context` (uses API tokens/cookies depending on implementation).

**Deployment & Operations:**
- **Local Dev:**: See `RUN_COMMANDS.txt` for three-terminal dev instructions: Backend (uvicorn port 8000), RAG (uvicorn port 8100), Frontend (`npm run dev` on port 5173).
- **Docker:**: Project includes `docker-compose.yml` and `.env.docker` example flow. Docker compose can bring up all services with `docker compose --env-file .env.docker up -d --build`.
- **First-time Setup:**: PostgreSQL must be available; backend and rag have venv setup steps and `requirements.txt`.

**Scalability & Future Improvements:**
- Offload vector store to a managed vector DB for scale (Pinecone, Chroma Cloud, or Weaviate).
- Add async/background workers for long-running transcription/embedding tasks (Celery/RQ) and job queue visibility.
- Harden auth (role-based access, rate limiting) and add automated tests for ingestion pipeline.
